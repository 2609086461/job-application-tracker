# 面经排版与内容骨架

这是一份可调整的写作骨架，不是必须填满的表单。资料丰富时采用详细版；只有面后文字回忆时采用精简版。两者都保持“原始事实”和“事后补充”的分界。

## 详细版：录音或完整转写

标题：`公司｜岗位｜轮次复盘（面试日期）`

开头用短行写公司、岗位、轮次、日期、录音时长或材料来源，以及转写错误和待核对事项。未确认日期不要伪装成确定日期。

1. 先看结论：整体信号、做得好的地方、主要薄弱项、可能继续追问的问题。所有评价都指向具体问答或表现；不能根据时长、闲聊或语气断言是否通过。
2. 面试流程还原：按时间顺序概括自我介绍、项目与技术追问、行为题、反问、面试官业务介绍。必要时标注时间戳。
3. 逐题完整复盘：每题用三级标题，下面按证据情况组织“原问题 / 当时回答 / 追问或明确反馈 / 准确处与问题 / 机制与工程边界 / 可复述回答 / 待核对项”。不要为没发生的反馈留一个虚构段落。
4. 反问与面试官答复：保留双方实际说法，区分明确答复与自己的理解。面试官主动介绍的公司或团队信息也放在这里或独立短节。
5. 下一轮准备：按优先级列出少量行动；每项写清要补的事实、验证方法或练习题，而不是泛泛“加强基础”。

## 精简版：面后文字回忆

标题与基本信息后，先列真实流程，再给整体评价和逐题复盘。每题至少保留题目、已知的本人回答、简明纠错/讲解和一段面试可说的参考回答。对未记下的答案、追问或反馈明说“回忆中未记录”。最后列最重要的改进点和下一轮准备，不为篇幅照搬详细版的每个小节。

## 逐题示意（虚构，不作为任何人的经历）

### 3. 为什么选择每 10 ms 更新一次控制量？

**当时回答（按回忆归纳）：**“大约每 10 ms 算一次，觉得这个速度够用。”

**面试官反馈：**未记录；不要推测其满意或不满意。

**需要修正：**10 ms 是周期，对应 100 Hz。回答只给数字，没有解释传感器刷新率、计算耗时和被控对象动态如何共同约束周期。

**讲清原理：**更新过慢会增加控制延迟；盲目加快则可能重复使用旧测量、放大噪声并增加处理负担。应结合实测响应、稳定性和资源占用选取周期。

**可复述回答：**“控制周期是 10 ms，也就是 100 Hz。我会先确认传感器能否按这个速度提供新反馈，再测量单次计算耗时和阶跃响应，比较响应速度、超调与资源占用后确定周期。这个数字是基于这些测试选的，而不是越快越好。”

**待核对：**当时的传感器更新率和实测阶跃数据；没有证据就不要填具体数值。

## 排版原则

- 一级标题用于全文标题；二级标题用于“结论、流程、逐题、反问、下一轮”等章节；三级标题用于具体问题。段落短，重点用少量加粗，不把所有正文都变成列表。
- 对比项多且关系清楚时才用表格；平台不支持原生表格就改为短段落或列表，不显示 `|---|` 等 Markdown 表格源码。
- 代码、公式和步骤只在帮助解释时出现；计算写明单位与口径。口头参考答案与原回答在视觉上区分，可用引用块，但不要让每题堆满重复标签。
