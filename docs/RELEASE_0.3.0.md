# v0.3.0 更新说明：搜索、面经与待办关联

本版更新的是可复用程序，不包含任何使用者的投递记录、邮件、面经正文或账号配置。

## 投递记录

- 按公司名称搜索，可与进展筛选组合使用；搜索忽略公司名中的空格并且不区分英文大小写。
- 进展筛选包括仅投递、测评、笔试/机考、一至三面、Offer 和已结束。一条记录可以同时符合多个阶段。
- 显示匹配数，每页 20 条。改变搜索或筛选条件时回到第一页。
- 公司名仅在原始记录含有效投递链接时可点击；本版不会凭空生成链接。

## 最近面经

- 私有看板可从用户自己的飞书复盘索引读取公司、岗位、轮次、实际时间和文档链接，按时间倒序展示。
- 支持公司搜索、每页 10 篇和点击直达。没有公司名或有效文档链接的索引项不会展示。
- 在私有 `看板程序/.env` 中设置 `REVIEW_APP_TOKEN` 与 `REVIEW_TABLE_ID`，并给飞书应用该表的读取权限。表格至少需要「公司」「复盘文档」字段；「岗位」「轮次」「实际时间」「记录名称」可选。
- 未配置或索引读取失败时，主看板仍可使用。公开只读接口始终返回空面经列表，不暴露私人的复盘链接。

## 求职待办

- 邮件待办与飞书任务合并展示，已完成事项默认放入已处理历史。
- 面试、笔试/机考、其他事项分别采用高、普通、低的默认优先级；私有看板可手动调整并恢复自动排序。
- 未关联任务的邮件可在管理模式下重试同步；定时同步获准写入飞书时也会重试遗漏任务，即使没有新邮件。
- 完成任务时，通过邮件来源键及同公司主题等安全匹配关系清理对应待办；不同轮次和场次仍需区别处理。
- 截止时间轴只展示有明确未来时间且尚未处理的事项。

## 升级和验证

从 v0.2.0 升级无需迁移个人数据。先备份自己的 `业务数据/`、`历史备份/` 和 `.env`，确认工作区没有未提交修改，再按 [UPDATES.md](../UPDATES.md) 拉取版本。进入 `看板程序` 执行 `python -m unittest discover -s tests -v`，通过后再重启服务。

本版离线测试为 132 项通过，前端内联脚本语法检查和 `git diff --check` 通过。离线测试不代表用户自己的飞书权限、邮箱同步或线上部署已经验证；这些需要在各自环境中单独检查。
