# 与 Codex 飞书机器人的可选联动

秋招看板和 Codex 飞书机器人是两个独立项目：不安装机器人也能使用本地看板，不安装
看板也能把机器人用于其他项目。希望在手机飞书里发送录音、整理面经或维护看板时，再把
两者连接起来。

## 最短联动方式

1. 先分别完成机器人和看板的本地验收。
2. 在机器人中把本仓库绑定为一个项目，让 Codex 的工作目录能够读取本仓库的
   `AGENTS.md` 和 `.agents/skills/`。
3. 为机器人提供本仓库的运行环境和私密配置访问路径，但不要把 `.env`、业务数据或
   语音服务密钥提交到 Git。
4. 在自己的飞书中创建“秋招复盘库”和复盘索引，并把标识写入私密环境变量。
5. 可选配置豆包录音识别凭据；先用一段无敏感信息的短录音验收。

录音识别凭据文件使用下面的字段：

```text
DOUBAO_SPEECH_APP_ID=
DOUBAO_SPEECH_ACCESS_TOKEN=
DOUBAO_SPEECH_RESOURCE_ID=volc.seedasr.auc
```

Windows 默认私密位置是 `%LOCALAPPDATA%\CodexFeishuLocal\doubao-asr.env`；云端机器人默认
把宿主机 `.codex-local/speech/doubao-asr.env` 只读挂载到容器。文件不能提交到 Git，也
不要把内容粘贴到飞书聊天。云端文件应只允许所有者读取。

## 交给 Codex 的提示词

```text
请把当前秋招看板项目绑定到我已经运行的 Codex 飞书机器人。
先阅读 AGENTS.md、AI_SETUP.md、docs/CODEX_BOT_INTEGRATION.md 和 .agents/skills。
不要复制他人的飞书 token、邮箱授权码或业务数据。
先只读检查机器人能否访问本项目，再配置我自己的面经目录和索引。
录音识别需要单独说明第三方处理与费用；先用短录音测试。
任何飞书写入先给我预览，得到确认后再执行。最后分别验证：普通问答、录音转写、
面经归档、索引更新以及看板“最近面经”链接。
```

## 验收结果

- 飞书发送普通消息时机器人正常回复。
- 发送短录音并要求“只给草稿”时，不会写入文档或索引。
- 明确要求“整理并归档”后，只创建或更新当前轮次的一条记录。
- 刷新看板后，“最近面经”可以搜索并打开该飞书文档。
- 一面、二面和 HR 面分别保存，互不覆盖。
